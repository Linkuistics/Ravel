# book-figure-installed-files-k114

## Goal

Port the UML deployment view, which needs nested directory enclosures that no
earlier figure has, and report its layout cost.

## Context

- Figure: `installed-files`. Host enclosure around `PREFIX`, which holds
  `bin/ravel` and a `libexec/ravel` directory of one executable and three file
  groups; one dashed discovery arrow; the PlantUML source stacks the file groups
  with hidden links. Directory tabs and outlines must not cross labels (a past
  art pass fixed a label that crowded an outline).
- Record design (`book-figure-layout-record-k120`, survey option B): `_deployment.typ` returns a layout record (plain data, no style) and the figure source passes it to `_draw.typ`'s render; nothing here draws. Each regenerated figure commits `<figure>.layout.json` beside its SVG (`book-figure-layout-json-check-k122`), and it is shipped sketched at roughness 2 with keys crisp (`book-figure-record-and-draw-k121`).
- New engine code: `_deployment.typ` (nested enclosure with tab, executable and
  file-group artifacts, dashed dependency). Keep it small; nothing else in the
  book uses it.
- Preserve: keep the CLI and worker from one build together; outlines group
  directories; a file group lists separate files relative to `libexec/ravel`;
  editing adjacent sources does not replace embedded modules; archive-only
  README and licence remain identified.

## Done when

- `installed-files.puml` is replaced by a committed `.typ`, regenerated SVG and `.layout.json`,
  with the key and file-path text unchanged except where a difference is listed.
- The decision log records the layout cost as numbers (see
  `book-figure-source-components`) and whether the cost table in
  `book-figure-migration-k108` held.
- `task docs:figures`, `task docs:book:build` and `task check` pass.

## Decisions (running log)

- 2026-10-17 — `installed-files` is ported to `installed-files.typ` (29 lines, 8 of them the key) on a new `_deployment.typ` (181 lines, 44 of them comments), with the regenerated `installed-files.svg` (160 KB) and `installed-files.layout.json`. `installed-files.puml` is removed. `_draw.typ` and `_style.typ` are unchanged: the record uses shapes `_draw.typ` already had (polygons for the enclosures and the page icons, a box per artifact, a dashed line for the dependency), so the one new primitive the k108 table named, "nested enclosures with tabs", is a layout function and no drawing code. One shared helper moved: `fit` (the measured wrapping width) went from `_c4.typ` to `_layout.typ`; the other eight figures' SVGs and records regenerated byte-identical (`task docs:figures:update` rewrote only `installed-files`).
- 2026-10-17 — Design choice: placement in `_deployment.typ` is automatic, where `_c4.typ`'s is manual. An enclosure is a container, so the figure source is a tree (`node`, `dir`, `artifact`, each enclosure a `row` or `col` with a `gap` and a `pad`) and the module sizes every box from its measured text, inside out. A row aligns its children on the centre of the first artifact each one holds, which is why `bin/ravel` → `ravel-policy` is one straight dashed line although the worker sits one directory deeper; the hidden links of the PlantUML source (stacking the three file groups) are the `col`. A directory's name is inside a tab sized to the name, so no outline can cross a label by construction (the past art pass's concern); the node's name sits below its top face. Nothing else in the book uses the module.
- 2026-10-17 — Layout cost, as numbers: 5 artifacts (2 executables, 3 file groups), 3 enclosures (the Host node and two directories, nested three deep), 1 dependency. Coordinates written: 0. Relations routed by hand: 0 (the one arrow takes the straight route because the two first artifacts' centres align). Label moves: 0. Label placement chosen: 1 wrapping width (the worker's `limit: 210`; the 240 default wrapped "embedded" alone onto a last line, where the old figure broke after "static"). Renders to settle: 2 (the first was structurally right; the second changed that one number). Minutes of work: not clocked; about 10 to 15, an estimate, nearly all of it writing the new module, since the figure source took one write and one edit and each render took under a second. The reading of `_c4.typ`, `_draw.typ`, the old source and `figures.md` beforehand is not counted.
- 2026-10-17 — Was the k108 table right? It estimated Medium ("new primitive, little routing"); the actual is Medium for the module and Low for the figure: the new code was the cost (a 181-line layout module, with a recursive measure and place), and the figure has none of the per-figure cost the other views carry (no coordinates, no routes, no label moves, one wrapping width). The estimate's reasoning, "nested enclosures with tabs; no edge routing", held. What it did not say is that automatic placement would remove the per-figure cost altogether; for the next figure of this kind (a second deployment view, a Part III or IV diagram of installed paths) the cost is a source of a few lines. This says nothing yet about the two state views, which have fan-out and long guard labels and need their own layout module.
- 2026-10-17 — What was clumsy: (1) an artifact's `limit` is a number in points chosen by eye, and a name longer than it wraps at a hyphen (seen in a scratch copy with `a-much-longer-file-name-than-any-other.md`: it broke after "file-"); (2) a row aligns on the first artifact in each child, with no way to say "align on the second", so a figure whose dependency joins two later artifacts would need a new option; (3) `dep` runs only from an artifact to one on its right (it asserts so), because that is the one shape this figure has. None needed a change here.
- 2026-10-17 — Facts and key lines are preserved. A script (`python3 -I`) compared the 17 quoted strings, title and key lines of the old `.puml` (taken from `HEAD`, typographic apostrophes normalised) with every text in the new layout record and found none missing; with `examples/sample.ts` removed from the haystack, and again with the last key line removed, it reports exactly that string missing, so it can fail. Differences are listed in `docs/book/figures.md` ("Differences from the PlantUML deployment output"): module-placed enclosures with sized tabs in place of PlantUML's graph layout and hidden links, a drawn page icon, measured wrapping, the shared arrowhead and stroke weight, sketched style at roughness 2 with a crisp key, and an SVG of paths with no `<text>`. The key and the file paths are unchanged. The preserved facts: the CLI and the worker sit together in one PREFIX (one build), outlines group directories, each file group lists separate files relative to `libexec/ravel`, "Editing adjacent sources does not replace embedded modules" is a key line, and the archive-only README and licence stay in the last key line.
- 2026-10-17 — The k122 control: changing the `prefix` row's `gap: 70` to `gap: 80` makes `task docs:figures` fail on both `installed-files.layout.json` and `installed-files.svg`; restoring it passes. A scratch copy with a fifth artifact (three long lines) rendered with no other edit, every box re-placed, no outline across a label (the scratch file was deleted).
- 2026-10-17 — `docs/book/figures.md` now says the deployment view is on `_deployment.typ` (a "What the deployment layout covers" paragraph, the effort counts, the differences list), says six modules hold the Typst side, and gives the SVG sizes (nine figures 1.46 MB, of which the two PlantUML ones are 52 KB); the single-engine-risk sentence names only the state diagram now.
