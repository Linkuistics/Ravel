## Decisions (running log)

- The source observation separates successful selected-scope composition from
  direct native entry. The runner installs process-global cancellation handlers
  without a return-time disposition guard, and its first-call SIGCHLD repair is
  retained. `EntrySignals` supplies child state, not restoration of the host.
  A native returning-call contract cannot infer host restoration from this API.
  This is a source counterexample, not a runtime failure observation or a target
  selection. The CLI's live selection guard restores its saved INT/TERM/HUP
  dispositions; its executable lifetime remains a distinct boundary.
- The textual acquisition inventory was derived before the new views. Selected
  output/channel failures do join front cleanup without an ending, but partial
  workspace/channel allocation has destructor-only removal whose error never
  reaches settlement. A complete all-acquisition cleanup claim is unsupported.
- Source error-path replay found a consumed runner signal missing from both
  wait-observation and reap-error returns, and successful worker conversation
  returning despite an unchecked teardown wait error. A conditional interactive
  pre-exec handoff/exec-failure path also bypasses lease reclaim. These are
  missing premises under the existing promises, not authorised exceptions.
  Result suppression survives the runner error; signal propagation need not.
- One fresh read-only reviewer, `acquisition_contract_review`, independently
  reconstructed exception-path retention rather than ranking variants. All
  three reported findings (runner interruption loss, unchecked worker wait,
  native host restoration) are valid/actionable against exact source. None is
  classified as a contract misread, accepted trade-off or noise. This agreement
  is one aimed source review, not runtime evidence or independent human use.
  Product repairs and runtime discrimination are outside this mandate and need
  prospective scope/funding; no second in-session reviewer is available.
- The current-state completion spec was qualified in place, with detailed
  source anchors/inventory in `docs/result-job-source-evidence.md`. Component,
  runner and existing worker/job ADR explanations now distinguish required
  promises from failure-path discharge. No ADR choice changed and no new ADR
  meets the hard-to-reverse/trade-off test. Existing package/target decisions
  remain unselected, and product source still matches the fixed reference.
- Presentation checks used `task --list-all` and `task docs:result-job PORT=8874`.
  The default 8774 port was occupied and returned no page, so the task's existing
  port override supplied the checked view without touching the old server.
  All four Mermaid views rendered after replacing sequence-label semicolons;
  the ownership view was stacked for desktop width. A fresh acquisition deep
  link reached the intended rendered view. Narrow native-entry labels were
  inspected at 390 pixels and the override reset; full mobile/dark usability
  remains unqualified. A scratch link check was corrected to load each target
  viewer's own manifest, then passed; the original instrument's components-view
  assertion was not a document defect. These checks establish presentation

- The bounded result is **unsupported for universal completion settlement**,
