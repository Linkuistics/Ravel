# rhai-llm-removal-k63

## Goal

Remove `ravel::llm` and everything that exists only for it. That is the LLM adapter, Rig, its HTTP client and TLS stack, the two LLM budgets, and the notice members for LLM calls. The product keeps working. A policy asks a model through `ravel::run_harness` instead.

## Context

- The input is the brief of `rhai-llm-calls-k15`, and the sections "LLM calls through a harness", "Evaluation budgets and their composition" and "Errors and refusals" in `docs/specs/policy-evaluation.md`.
- The leaves `rhai-llm-adapter-proof-k54`, `rhai-llm-anthropic-call-k55`, `rhai-llm-bounds-k17`, `rhai-llm-budgets-k18` and `rhai-llm-openai-types-k19` built the code that goes. Read their running logs to find every place they touched.
- The code to remove is the module `src/llm`, the worker side `rhai_worker/llm_call.rs`, the tests `tests/rhai_llm.rs` and `tests/rhai_llm_openai.rs`, and the fake provider server and seam under `tests/support`. Search for the rest, because the list ages.
- `rhai-json-check-k62` moved the schema checker out of `src/llm`. Keep it. Remove only the old tests that remain.
- `rhai-endpoints-removal-k64` follows. It removes the `endpoints` settings key and `ravel::endpoints()`. This leaf keeps both, and the product works with them unused.
- `excluded_grant` keeps the names that 1.x excludes, such as `NODE_OPTIONS`. Only its clause for an `apiKeyEnv` goes, and it goes with the endpoints. Leave it for the next leaf.

## Done when

- `ravel::llm`, the budgets `llmCalls` and `llmOutputTokens`, and the refusal `llm_budget_exhausted` are gone from the code, the tests and the notice. A settings file with `budgets.llmCalls` refuses as an unknown budget.
- The notice of the Rhai path keeps schema version 2. `llmCalls`, `worker.rigVersion` and the LLM members of `bounds` are gone.
- The LLM adapter is gone, with its HTTP client and its body bounds. Rig, reqwest and rustls are gone from `Cargo.toml` and `Cargo.lock`. A dependency that only they needed goes too. Prove each removal with `cargo tree`.
- The tokio runtime stays only if the worker front or the reader still needs it. Record which crates remain and why.
- The cross-build proof for `ring` in `rhai-llm-adapter-proof-k54` has no subject. Remove any script, task or note that exists only for it.
- The `endpoints` key and `ravel::endpoints()` still work, and a test still covers them.
- The tests of the scenarios "LLM-assisted selection", "Another purpose", "A structured answer that does not match", "A failed call and a fallback" and "Leak probes" are gone with the fake provider. `rhai-llm-call-scenarios-k67` rebuilds them through `run_harness`. Name the removed tests in the running log, so that leaf can match them.
- The TypeScript path works as before. `task check` and `task test` pass.

## Notes

- Check the claim that nothing remains with a sweep. Enumerate every token that matches `llm`, `rig`, `reqwest`, `rustls` and `ring` in tracked files, then classify each one. Run a control that finds a known hit.
- A dead-code lint can fire on an endpoint field after the call goes. Remove only what the lint names, and leave the rest to `rhai-endpoints-removal-k64`.
- The book and the spec describe the final state already. Do not edit them here, except an excerpt that moved.
- If the leaf proves too big, decompose it. A natural cut is the tests first, then the adapter and the dependencies.

## Decisions (running log)

- **One leaf, in the order the compiler allows.** Tests and the fake provider first, then the adapter and the worker side, then the budgets and the notice, then the dependencies. It did not need a decomposition. The leaf is a deletion, and each step compiled.
- **The code that went.** `src/llm` (`mod.rs`, `shape.rs`, `transport.rs`, `tests.rs`, `tests/openai.rs`), `rhai_worker/llm_call.rs`, `tests/rhai_llm.rs`, `tests/rhai_llm_openai.rs`, `tests/rhai_llm_schema.rs`, and `tests/support/llm_server.rs` with `tests/support/llm_seam.rs`. Around them, the `llm` host call in `host.rs` (the adapter, `attempt`, `debit`, `exhausted` and the two counters), the `llm` function and registration in `bridge.rs`, `LlmCall` in `mod.rs`, `serve.rs`, `front.rs` and `choice.rs`, `Choice::llm_calls`, `budget_refusal` and the `llm_budget_exhausted` arm in `choice.rs`, the `llmCalls` member of the notice in `run.rs`, `LLM_CALLS_*` and `LLM_OUTPUT_TOKENS_*` in `limits.rs`, the two keys of `budgets` in `settings.rs`, and `Schema::raw` in `schema.rs` (only `to_rig` used it).
- **The budget keys are unknown budgets.** `budgets.llmCalls` and `budgets.llmOutputTokens` refuse as `settings_invalid` at their location, and the message says the only budget is `harnessRuns`. The new test `the_budgets_of_the_removed_llm_call_are_unknown_budgets` fails when the settings reader accepts `llmCalls` (seen) and passes after the revert.
- **The notice keeps schema version 2.** It has no `llmCalls`, and `bounds` holds `harnessRuns` and no LLM budget. `worker` never held a `rigVersion`, because the notice code only planned it. `ravel::remaining()` returns `ms`, `harnessRuns` and `sources`, as the spec says. The bound names on the wire between the front and the worker are seven, not nine.
- **`rhai-endpoints-removal-k64` still has its subjects.** `endpoints.rs`, `Directory::endpoints`, `ravel::endpoints()`, the `endpoints` frame, the `apiKeyEnv` clause of `excluded_grant`, and the `url` crate stay. The tests in `tests/rhai_settings.rs` that cover them pass. No dead-code lint fired on an endpoint field, so I removed none.
- **Crates that went, proved with `cargo tree`.** Before the leaf, `cargo tree -p ravel` listed 170 distinct crates. It lists 92 now. `cargo tree --workspace --target all -e normal,build,dev -i NAME` answers "did not match any packages" for `rig-core`, `rig-http`, `reqwest`, `rustls`, `ring`, `aws-lc-rs`, `hyper`, `h2`, `tower`, `schemars` and `thiserror`, and answers `rhai v1.27.0` for the control. The direct dependencies `rig-core`, `rig-http`, `reqwest`, `rustls` and `serde` left `crates/ravel/Cargo.toml`. Nothing used `serde` by name, because `serde_json` brings it. `Cargo.lock` lost about 1,040 lines.
- **Crates that stay, and why.** `tokio` stays with the features `rt`, `net`, `time`, `macros`, `sync` and `io-util`. `serve.rs` uses the runtime, `UnixStream`, `select!` and the timers, `reader.rs` uses `oneshot`, and `front.rs` builds the current-thread runtime. `url` stays for `endpoints.rs` until k64. `serde_json`, `sha2`, `getrandom`, `libc`, `tempfile`, `clap`, `rhai` and `keyed-launch` are used as before.
- **Removing Rig changes two `serde_json` features.** `rig-core` turned on `preserve_order` for the whole build (k54 recorded it) and `float_roundtrip`. Both are off now. The first matters: `ravel::json_encode` promises members in ascending order (`helpers.rs`, "without the `preserve_order` feature"), and that is true again. `context.rs` keeps its explicit `sorted`, because a later dependency can flip the feature again, and its comment no longer names Rig. The second is a change of reading: without `float_roundtrip`, `serde_json` can read a rare decimal with 17 or more digits one unit in the last place away from the nearest `f64`. The spec asks for the shortest form on output only, no test covers a hard decimal on input, and the code ran this way before k54. I changed nothing. If the owner wants exact input, enabling `float_roundtrip` on `serde_json` is one line.
- **The ring cross-build proof has nothing to remove.** k54 ran `task release:smoke` for the three archive targets and recorded the result in its log. No script, Taskfile task, CI step or note exists only for `ring`. `scripts/release-smoke*.sh` prove the archive targets and stay. `grep` over `scripts`, `Taskfile.yml`, `release.toml` and `crates/ravel/notices` finds no `ring`, `rustls`, `reqwest` or `rig` token.
- **The sweep.** I listed every token that matches `llm`, `reqwest` or `rustls` as part of a word, or `rig` or `ring` as a whole word, in the 281 tracked files outside `docs/evidence`, `docs/research`, `.grove` and the lockfiles of `node_modules`. Then I classified each token. Code and scripts: prose about the LLM session in a harness (`README.md`, `CONTEXT.md`, `CHANGELOG.md`, `cli.rs`, `ste.test.sh`) stays; `grove-llm` is a tool name (`installed-smoke.sh`, `release-archives.test.sh`); "LLM endpoint" in `endpoints.rs`, `environment.rs`, `inputs.rs`, `front.rs`, `settings.rs` and `Cargo.toml` is the endpoint feature that k64 removes; the `llmCalls` and `llmOutputTokens` tokens in `settings.rs`, `tests/rhai_settings.rs` and `tests/rhai_policy.rs` are the tests and the message that make the old keys refuse. The book, the spec, the ADRs and the design views describe the final state, and I did not edit them. The controls: the same listing finds the docs hits, so the pattern is not blind. At `HEAD` the same pattern over `crates/ravel/src` and `crates/ravel/tests` returned 289 lines, so it comes back dirty on a subject that is wrong. `task docs:excerpts` passes (8 excerpts), so no excerpt pointed into the removed files.
- **Tests removed with the fake provider, 141 in all.** `rhai-llm-call-scenarios-k67` rebuilds the five scenarios through `run_harness`. This map names the old tests.
  - "LLM-assisted selection": `select_asks_an_endpoint_to_classify_the_prompt_and_routes_on_the_answer` (in `rhai_llm.rs` and in `rhai_llm_openai.rs`), `load_context_asks_for_a_summary_that_select_receives`, `a_call_at_the_top_level_of_the_entry_runs_too`.
  - "Another purpose": `load_context_asks_for_a_summary_that_select_receives`, which asks for a summary and not a route.
  - "A structured answer that does not match": in `rhai_llm_schema.rs`, `an_answer_that_does_not_match_fails_the_call_with_the_location`, `an_answer_that_is_not_json_fails_the_call`, `an_answer_that_matches_the_schema_of_the_script_passes_whatever_rig_sent`, `a_large_answer_that_matches_reaches_the_script_whole`, `an_answer_nested_past_the_converter_fails_the_call_and_one_at_the_limit_passes`, `a_long_key_in_a_message_is_cut`, `a_call_without_a_schema_sends_none_and_returns_no_json`. The schema subset itself is covered by `tests/rhai_json_check.rs` and `src/schema.rs`.
  - "A failed call and a fallback": `a_rate_limit_is_data_and_the_policy_falls_back_to_a_second_endpoint`, `a_rate_limit_on_one_type_falls_back_to_an_endpoint_of_another_type`, `each_failure_of_an_endpoint_is_a_code_that_the_script_can_read`, `a_failed_response_has_the_shape_of_the_spec`, `an_endpoint_can_refuse_a_schema_of_the_subset_and_the_call_selects_no_fallback`.
  - "Leak probes": `the_credential_reaches_the_server_only_in_its_header_and_no_probe_finds_it`, `an_endpoint_that_echoes_the_credential_in_any_field_of_an_answer_leaks_nothing`, `a_redirect_is_not_followed_and_the_credential_goes_nowhere_else`, `the_credential_in_a_json_answer_is_redacted_before_the_value_is_read`, and `the_credential_reaches_the_server_only_in_its_header_and_an_echo_leaks_nothing`. The flag-grant test `a_flag_grant_of_a_credential_refuses_before_any_worker` also left `rhai_llm.rs`, and `tests/rhai_settings.rs` still holds its twin `a_flag_grant_of_a_credential_refuses_as_excluded_grant_with_exit_2_and_no_worker`.
  - Stop and cancellation with a call in flight, which the spec scenarios "A stalled harness" and "A signal after the deadline" now own: `a_stalled_endpoint_ends_the_evaluation_at_the_deadline_and_the_connection_closes`, `a_signal_during_a_call_in_flight_closes_its_connection_and_launches_nothing`, `a_signal_that_arrives_after_the_deadline_wins_and_the_report_keeps_the_timeout`, `a_trust_store_that_blocks_cannot_hold_the_whole_deadline`.
  - Budget tests with a harness analogue (`harness_budget_exhausted`): `a_ninth_call_in_try_still_ends_the_evaluation_as_llm_budget_exhausted`, `the_owners_call_budget_replaces_the_default_and_a_zero_budget_forbids_every_call`, `a_call_that_fails_before_it_is_sent_uses_no_budget`, `a_budget_breach_reports_the_line_of_the_call`, `the_notice_lists_the_effective_budgets_among_its_bounds`.
  - The rest tested the adapter, Rig, the wire formats, the body bounds and the endpoint calls (`src/llm/tests.rs`, `src/llm/tests/openai.rs` and the remaining cases of `rhai_llm.rs` and `rhai_llm_openai.rs`). They have no analogue after the move.
- **Measured.** `task check` (format, shellcheck, worker build and probes, runtime integrity, worker types, `clippy --all-targets`, terminal recovery, then `cargo nextest run --locked --workspace`) passed on the final sources: 555 tests, none failed. The digest of `crates`, `scripts`, `Cargo.toml`, `Cargo.lock` and `Taskfile.yml` was the same before and after the run. An earlier run passed 554 tests, before I added `the_budgets_of_the_removed_llm_call_are_unknown_budgets`. `task test` runs the same nextest command, and `check.sh` ends with it.
