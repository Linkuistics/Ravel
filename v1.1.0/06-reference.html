The Ravel book

Reference

Use this chapter to find the command line, exit statuses, streams, environment rules, configuration and installed paths. A caller starts a session. The owner policy selects its managed process. Only the caller gives meaning to the opaque result. Each entry links to the chapter that teaches its use.

The entries describe the version that this book names, installed with Homebrew.

This chapter writes INT, TERM, HUP and KILL without the SIG prefix. Other signal names keep that prefix. Code and diagnostic text keep their literal names.

Command line

ravel, help and version

ravel takes one of two verbs: start-session or end-session. It has no help subcommand. The table gives the help and version requests.

RequestOutputStatus
ravel without a verbHelp on stderr.2
ravel --help, ravel start-session --help, ravel end-session --helpHelp on stdout. -h is the short option on all three command lines.0
ravel --version, ravel -VThe package version of the Ravel CLI on stdout. The version option belongs only to the top-level command.0

Help and version text is informational output, never an opaque result. See the first complete session for the two verbs in use.

After --, Ravel reads no more options. For end-session, put -- before a result that looks like an option. Inside a live session, ravel end-session -- '--help' sends the literal value --help. See result arguments.

start-session

ravel start-session --kind TEXT also needs exactly one of --prompt TEXT and --prompt-file PATH. It reads the owner settings, checks and evaluates the owner policy, then supervises the selected program. A refusal launches nothing, and Ravel tries no alternative route.

A successful invocation writes the sent result unchanged to stdout. This write occurs only after the reap, the confirmed absence of the process group and the required cleanup. Ravel does not interpret the result. See run a complete session and interpret the outcome.

All fifteen options below belong after start-session. Only --param, --policy-env and --runtime-read accept more than one occurrence. A repeated single-value option or switch is a command-line error. -h and --help are also available on this verb.

--kind TEXT

--kind is required and supplies request.kind unchanged. Its value is nonempty UTF-8. Ravel has no catalogue of kinds and gets no kind from a task file. Ravel gives the token no meaning. An absent or empty kind gives status 2. See supply the prompt and caller data.

--prompt TEXT and --prompt-file PATH

Exactly one of these two prompt inputs is required.

OptionSource of request.prompt
--prompt TEXTThe argument text, also when it starts with -.
--prompt-file PATHOne read of the file, relative to the caller’s working directory.

The prompt can be empty. It contains no NUL, is valid UTF-8 and has a maximum of 1,048,576 bytes (1 MiB). Ravel puts its bytes unchanged in request.prompt, with trailing newlines. Ravel adds no instructions to end the session. The policy decides how to give that text to its selected program.

An unreadable prompt file reports prompt_unreadable. Invalid encoding, a NUL or too many bytes reports prompt_invalid. Both give status 2. A command with no prompt input, or with both prompt inputs, also exits 2. Ravel does not implicitly read the prompt from stdin, and it refuses a prompt file that is a terminal. See supply the prompt and caller data.

Note: Shell command substitution removes trailing newlines before Ravel receives an argument. --prompt-file preserves those bytes. An operating system can set a smaller argument limit. This limit also applies when the policy puts a prompt from a file into the arguments of the selected command.

--task-file PATH and --task-id ID

These optional fields carry caller data. Invalid input gives status 2.

OptionRequest fieldValue and effect
--task-file PATHrequest.taskFileRavel joins the caller’s working directory and the given path to make an absolute UTF-8 path. It does not canonicalise or read the path. The file does not have to exist, and the path supplies no kind or task identity.
--task-id IDrequest.taskIdNonempty opaque UTF-8 with a maximum of 1,024 bytes. It can start with -. Ravel does not search for a task record.

See caller data for both fields.

--config PATH

--config selects a policy entry, relative to the caller’s working directory. Without it, Ravel uses $HOME/.config/ravel/policy.ts, which needs an absolute HOME. There is no repository search and no environment variable that selects a different policy. The entry resolves to a readable regular file. Its canonical path is UTF-8 and contains no ?. A symlink selects its real file, and the directory of that file is the base for relative imports.

An empty option value is malformed input, status 2. If Ravel cannot accept the entry file, the status is 3. A different entry does not move the settings file from $HOME/.config/ravel/settings.json. See define a policy and resolve its imports.

--param NAME=VALUE

--param adds a string to request.params, and it is repeatable with different names. The table gives the parts of each argument and their limit.

PartRule
NameNonempty UTF-8 without =. Each name occurs only once.
SeparatorThe first = separates the name from the value.
ValueUTF-8, possibly empty or with more = characters.
Whole argumentCan start with -.
Combined sizeAll names and values together have a limit of 65,536 bytes. The separators do not count.

A repeated name, a missing separator, invalid encoding or a total above the limit gives status 2. Ravel gives names and values no meaning. See caller parameters.

--context PATH

--context reads a regular file, relative to the caller’s working directory, as version-1 JSON policy context. Ravel validates it and records its canonical name, byte count and SHA-256. Without loadContext, the delivered document is this data with the measured sources attached. With a loader, the data is input to the loader, and the loader assembles the document that select receives. With no caller document and no loader, select receives undefined as its policy-context argument.

Ravel refuses an unreadable, invalid or oversized document with status 3. Malformed command-line syntax still gives status 2. This option supplies policy context, never a session-result context. See supply policy context.

--timeout-ms MS

--timeout-ms replaces the owner’s timeoutMs setting for this invocation. The table gives its syntax and values. Invalid syntax or range gives status 2.

PropertyValue
Input syntaxDecimal digits.
Inclusive range1,000–600,000 milliseconds.
Default, with no flag or setting30,000 milliseconds.

Ravel validates the settings before the flag replaces a value. Thus, an invalid owner setting fails even with a valid flag.

The deadline starts when the Ravel CLI spawns the policy worker. It covers the worker startup, the policy import, the policy-context loader and the selection. At expiry, Ravel stops the selection, attempts the teardown of the worker and exits 124 with no managed launch. Cleanup time is additional. The deadline does not limit the time that the managed process works. See set bounds.

--context-bytes BYTES

--context-bytes replaces the owner’s contextBytes setting. It takes decimal digits in the inclusive range 1–8,388,608 bytes. With no flag and no setting, the budget is 262,144 bytes. Invalid syntax or range gives status 2. Ravel validates the settings first. Thus, an invalid setting fails even with a valid flag.

The budget limits the caller document and the encoded policy context that selection receives, with the measured source records. It is also the maximum for a host source read. Ravel refuses data above a bound, and it does not truncate that data. context_too_large uses status 3. See policy context and bounds.

--policy-env NAME

--policy-env grants the policy worker one caller environment variable in addition to its base set. Repeat it to grant more names.

Grant propertyBehaviour
Owner settingsThe flags add to the owner’s policyEnv array.
Duplicate namesRavel merges them into one grant, in the order of their first occurrence.
ValueA grant carries the caller’s current value. An unset variable stays absent.
RecipientThe policy worker. This option does not grant a variable to the managed process.

A name is nonempty UTF-8 and contains no =. It cannot match a reserved grant class. A malformed name reports malformed_input, and a reserved name reports excluded_grant. Both give status 2. Grant diagnostics show each name and whether it is set, never its value. See grant environment names.

--confine

--confine restricts the filesystem access and the environment of the managed process. It uses macOS sandbox-exec or Linux bubblewrap. Confinement is off when the flag is absent. The owner policy and its worker stay outside confinement. Ravel tests the backend before policy evaluation. It never uses an unconfined launch in place of a confined launch.

The table gives the access of the confined managed process.

ResourceAccess
Canonical working directory and private run directoryWritable.
System runtime paths, selected executable and real executable file of the Ravel CLIReadable.
NetworkPermitted.
POSIX session and terminalA new POSIX session, with EOF on stdin. Ravel does not lend the caller’s controlling terminal.
EnvironmentRavel restricts the managed-process environment separately from the environment of the policy worker.

Filesystem grants cannot overlap the policy directory or the owner settings, and this rule also applies through symlinks. An unusable backend or input reports confinement_unusable, and an overlap reports confinement_overlap. Both give status 2. See confine the managed process for the layout and the operational limits.

Note: The project measured inherited signal settings, cancellation, cleanup and terminal recovery on aarch64 macOS and aarch64 GNU/Linux. For x86_64 GNU/Linux, the project built Ravel and ran it only under emulation. Native x86-64 qualification is still open. The support limits give the scope of these measurements.

--runtime-read FILE

--runtime-read adds one read-only runtime file to a confined launch, and it is repeatable. It needs --confine. Without that switch, the command exits 2. The path resolves from the caller’s working directory to a regular file that exists, and its canonical name is UTF-8. The option grants no directory tree.

Read-only grants stay read-only inside writable directories. If a grant is unusable or has an overlap, Ravel stops with status 2 before policy evaluation. See confinement grants.

--exit-dir DIR

--exit-dir gives the parent directory of the private result channel. The parent is a writable directory that exists. Ravel resolves it from the caller’s working directory. The table shows the parent for each form of launch.

LaunchWithout --exit-dirWith --exit-dir DIR
UnconfinedThe system temporary directory.DIR.
ConfinedThe private run directory.DIR, also as a writable grant.

The option chooses a parent, not a result filename or a persistent store. An invalid parent can report exit_dir_unusable with status 2. If Ravel later cannot allocate the result channel, it reports session_channel_unavailable with status 5. See choose a channel parent.

--json

--json replaces Ravel’s text routing notice and failure document with version-1 JSON on stderr. It does not change the result on stdout or the output of the managed process. It is off when it is absent, and it belongs to start-session. See streams and notices for the fields and the order of output, and read notices for their use.

Note: After a successful parse of the command line, a value such as --prompt '--json' is caller data, not a switch. If the parse fails, Ravel searches the argument words for an exact --json to choose the error format. Help, version and the help for a missing verb keep their usual display format.

end-session RESULT

ravel end-session RESULT sends one UTF-8 argument to the live enclosing session. The inherited RAVEL_EXIT_FILE identifies that session. The verb accepts no session ID, target or settings option, and it reads no policy or settings. -h and --help show the help of this verb. -- permits a result that looks like an option.

The table gives the inputs of end-session. Quote RESULT so that it stays one argument.

InputValue or effect
RESULTOne UTF-8 argument. It can be empty, multiline or Unicode, with a maximum of 1,048,576 bytes (1 MiB).
RAVEL_EXIT_FILEThe inherited path of the live session’s private result channel.
--Ends the options, so a value that looks like an option can follow as RESULT.
-h, --helpShows help, without a send.

Ravel keeps the first complete result that it receives. When that result arrives, Ravel starts to stop the harness. Thus, a second end-session and that shutdown are in a race: either can occur first. For example, another process in the group can send a result before Ravel stops that process. Ravel keeps the first result, even if the second command succeeds. The shutdown can stop the second command, or the removal of the result channel can make it fail.

A successful end-session exits 0 and prints nothing. It means only that the channel accepted the result, or that a valid first result was already present. It does not mean that the job ended or that the result reached the caller. A cancellation or a failure of required cleanup still returns no result to the caller.

end-session exits 1, with a text diagnostic on stderr, if the session-result context is missing, empty, stale or invalid. It also exits 1 for an oversized value or an I/O failure of the send. If the Ravel CLI finds an argument-count or encoding error, it exits 2. The operating system can set a smaller argument limit before the executable starts. See accept a result only after success.

Note: After Ravel detects the sent result, it gives a job that still runs 2 seconds. Then it sends TERM, waits up to 5 more seconds and uses KILL if necessary. If the direct child exits, Ravel stops the other group members before the reap, with no new grace period. Ravel can stop code that runs after end-session.

Exit statuses

For start-session, accept the result on stdout only when the final status is 0. Neither the exit status of the managed process nor an earlier successful end-session decides the result of the enclosing session.

Cancellation has precedence over an original failure. An original failure keeps its status if a later cleanup also fails. Otherwise, if the required cleanup fails, Ravel returns no result to the caller. All applicable cleanup reports stay as diagnostics. See outcome precedence.

The three signal statuses in the table follow the shell convention: 128 plus the signal number. Ravel attempts the cleanup and then raises the same signal again. Thus, a process API reports termination by a signal. If the propagation fails, Ravel reports the failure and uses the numeric status in its place. A caller that uses a process API handles both cases. If a signal is ignored or blocked when Ravel starts, that signal does not automatically cause a cancellation.

Note: KILL or another abrupt death can stop Ravel before it decides the final outcome. A signal that arrives after the final decision about cancellation can interrupt the result write. Neither case confirms the cleanup or that the caller received the complete result. A failed final write can leave a prefix on stdout. The operational limits describe these cases.

RAVEL_EXIT_FILE

RAVEL_EXIT_FILE is the inherited session-result context: the path that end-session uses to send the result to its enclosing session. The Ravel CLI sets it only for the managed launch. The policy worker never receives it. A nested launch replaces it only for its own managed process. The value of the outer caller does not change.

If the path is unset, empty or stale, end-session fails with status 1. Do not use it as a persistent result location or as an address across sessions. The result channel separates ordinary sessions. It is not a defence against hostile code that runs as the same user. See nested sessions and operational limits.

Policy entry and settings

policy.ts

$HOME/.config/ravel/policy.ts is the default owner entry. This default needs an absolute HOME. --config PATH chooses a different entry, relative to the caller’s working directory. There is no repository search, environment override or fallback policy.

The entry must resolve to a readable regular file, with a UTF-8 canonical path that contains no ?. A symlink uses its real file. The directory of the real file is the base for relative imports. If Ravel cannot accept the entry file, it exits 3 before owner code runs. See define a policy and resolve imports.

policy is the named export that Ravel evaluates. A default export alone is not sufficient. The export is a plain object, not an array or a class instance, with the four policy fields below. Trusted owner code runs outside the confinement of the managed process, in a separate worker that never receives a session-result context. After a successful selection, the Ravel CLI reaps the worker and removes its private directory before the launch. See policy evaluation.

settings.json

$HOME/.config/ravel/settings.json supplies owner defaults for start-session. --config does not move it, and XDG_CONFIG_HOME does not select it. A missing file, an absent or relative HOME or an empty JSON object supplies no settings. A file that exists must be a readable regular file that contains a JSON object. end-session reads neither settings nor policy. See set bounds and grants.

Policy context and host operations

Context and DeliveredContext

Context is version-1 JSON data. --context supplies it, or loadContext returns it. An absent optional field means unknown, which is different from a known empty object, array or string. Ravel refuses unknown top-level fields, for example program, args, argv, command, select, loadContext, env, environment, exec, shell and script. These names inside free-form JSON facts stay data. See supply policy context.

FieldAccepted valueTaught in

DeliveredContext adds the required measured to the accepted document and is deeply frozen. Neither the caller nor the loader supplies that field. Without a loader, selection receives the caller document with the measurements, or undefined if there is no document.

A loader replaces the document that select receives, but request.context still gives the caller’s original input. Ravel does not merge the two automatically. Ravel refuses a loader that returns nothing. See caller and delivered documents.

measured holds the successful reads in order. The caller’s --context document comes first when it is present, then the host reads, also repeated reads of one file. The separate limit of this list is 256 records. The compact encoding of the whole delivered document, with this list, must fit contextBytes. Source attribution and measurement do not prove who the author was or that a claim is true. See measurement and its limits.

  • a read beyond the source count
