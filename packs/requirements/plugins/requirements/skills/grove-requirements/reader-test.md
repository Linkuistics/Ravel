# Reader test — the procedure of a reader checkpoint

**This is a procedure reached on a condition, not a standing instruction.**
This skill's `SKILL.md` reaches it when this leaf holds a reader checkpoint.
A document contract declares the checkpoint. The session that cut the
document's leaf placed this leaf after the document's `proof`. In any other
`requirements` leaf, nothing on this page runs.

A reader checkpoint runs outside the editorial stages. The intended reader,
or a labelled stand-in, reads the document. You run the read and record what
it shows. You do not repair the document in this leaf.

## Before the read

<!-- tc: depart long-sentence because the conformance inventory pins this rule statement verbatim -->
**Before the read, state the audience, the reader tasks (find, understand,
use), the entry surfaces and the viewing environment. Confirm that figures
load there, and give the reader the steps that make them load.** Take each
value from the contract's reader checkpoints part.

## During the read

**An early comprehension failure stops the read; record the reader's words
and how far they got.** <!-- tc: depart semicolon because the conformance inventory pins this rule statement verbatim -->

<!-- tc: depart long-sentence because the conformance inventory pins this rule statement verbatim -->
**Observe find, understand and use through tasks, paraphrase of key terms or
plus–minus marking. Liking is not the outcome, and a guideline's counts are
not thresholds.**

## What the record holds

**Record the exact locations and entry surfaces the reader reports. Coverage
they did not report stays unknown, and a quoted passage does not establish a
route.**

<!-- tc: depart long-sentence because the conformance inventory pins this rule statement verbatim -->
<!-- tc: depart synonym-rotation because "mechanical checks" names an evidence class, not the action of confirming -->
**Keep model-proxy results, mechanical checks, human acceptance and task
performance apart. Label the proxy, and count probes that share one model
context as one reader. Do not infer which stage caused a verdict. Agreement
between independent readers is the validity signal.**

## After the read

<!-- tc: depart long-sentence because the conformance inventory pins this rule statement verbatim -->
**Route each correction to the owner of its class under the bounded
correction rule, with the reader's words attached. Schedule the next read
before dependent document work, starting it at the repaired entry.** The
document's editorial stages state the bounded correction rule.

<!-- tc: depart semicolon because the conformance inventory pins this rule statement verbatim -->
**Acceptance with a bounded correction can coexist with later ambitions;
record those ambitions as later work, not as instructions to rewrite now.**
